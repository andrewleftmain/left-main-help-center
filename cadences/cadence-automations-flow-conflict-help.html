Cadence Automations: Flow Conflict Help

Cadence Automations: Flow Conflict Help

Companion to: Cadence Automations: Internal Support Guide

Purpose

Use this guide with the Cadence Automation Readiness Check when reviewing a customer’s existing Salesforce Flows.

For each Cadence automation the customer wants to enable:

  1. Find the matching automation in this guide.

  2. Review active flows on the same or related object.

  3. Compare the flow’s trigger, entry conditions, and actions with the Cadence automation.

  4. Help the customer choose one automation method for each overlapping process.

The customer should either:

  • Deactivate the conflicting flow and use Cadence automations, or

  • Keep the flow active and leave the overlapping Cadence automation disabled.

⚠️ Critical Rule

Never run a Salesforce flow and Cadence automation that perform the same action.

When moving away from a flow, deactivate it. Do not delete it. Deactivation preserves a rollback path if the customer needs to restore the previous configuration.

How to Review a Flow

For each flow identified by the Cadence Automation Readiness Check, review the following five areas.

1. Object

Confirm which object starts the Flow:

  • Lead

  • Opportunity

  • Contact

  • Transaction

  • Interested Buyer

  • Task

Start with flows on the same object as the automation. Related-object flows may also affect behavior and should be reviewed when applicable.

2. Trigger

Identify when the flow runs:

  • Record is created

  • Record is updated

  • Record is created or updated

  • Scheduled

  • Invoked by another flow, Apex action, or process

Compare the flow trigger with the Cadence automation trigger.

3. Entry Conditions

Review the fields and values that determine whether the Flow runs.

Pay particular attention to:

  • Status

  • Stage

  • Lead Source

  • Reason for Selling

  • Appointment Date/Time

  • Lead conversion

  • Date or time conditions

  • ISCHANGED() logic

4. Actions

Determine whether the flow:

  • Creates a Cadences__c record

  • Calls an Add Cadence Apex or invocable action

  • Creates SMS, email, or task follow-up records directly

  • Stops or pauses a cadence

  • Enrolls a different Cadence Library

  • Changes a field monitored by Cadence automations

  • Re-enrolls a cadence after another automation stops it

5. Activation Status

Only active flows can create an immediate conflict.

Draft and inactive flows may be ignored for current behavior, although they can help explain the customer’s prior configuration.

Lead Automations

1. Enroll New Leads

What It Does

When a Lead is created, the automation evaluates up to three routing rules in priority order.

Rules may use:

  • Status

  • Lead Source

  • Reason for Selling

The first matching rule determines the Cadence Library. If no rule matches, the default library is applied.

Trigger: Lead is created.

Look for These Flows

Review active Lead flows that:

  • Run when a Lead is created or created and updated

  • Enroll a Lead into a cadence

  • Branch on Status, Lead Source, or Reason for Selling

  • Assign different Cadence Libraries based on Lead information

  • Change Status or Lead Source during record creation

  • Have names such as:

    • New Lead Cadence

    • Lead Assignment

    • Lead Routing

    • Auto-Enroll

    • New Lead Follow-Up

🔴 High Risk — Enroll vs. Enroll

The Lead may be enrolled into multiple Cadence Libraries and receive duplicate outreach.

🟡 Review Carefully — Field Driver

A create-time Flow that changes Status, Lead Source, or Reason for Selling may affect which routing rule is selected.

🔵 Support Action

Compare the customer’s existing routing logic with the available Cadence automation rules.

  • If the logic can be recreated using up to three routing rules, configure and test the rules, then deactivate the Flow.

  • If the Flow uses more complex logic than the automation supports, keep the Flow and leave this automation disabled.

2. Lead Follow-Up Status Trigger

What It Does

When a Lead’s Status changes to Follow Up:

  1. The active cadence is stopped.

  2. The selected follow-up Cadence Library is enrolled.

Trigger: Lead is updated, Status changes, and Status equals Follow Up.

Look for These Flows

Review active Lead flows that:

  • Run when Status changes to Follow Up

  • Stop the active cadence

  • Enroll a follow-up cadence

  • Swap Cadence Libraries whenever Status changes

  • Re-enroll a cadence after another process stops it

🔴 High Risk — Enroll vs. Enroll

Both processes may enroll a follow-up cadence.

🔴 High Risk — Fighting Automations

A flow may re-enroll a cadence the native automation just stopped.

🔵 Support Action

Determine whether the customer wants the Flow or the Cadence automation to control the Follow Up transition. Deactivate the overlapping process.

3. Stop Cadences When a Lead Is Converted

What It Does

When a Lead is converted, active cadences on the Lead are stopped.

Trigger: IsConverted = True

Look for These Flows

Review Lead conversion flows that:

  • Stop cadences during conversion

  • Copy cadence information to the resulting Opportunity

  • Enroll the new Opportunity in a cadence

  • Create follow-up activity on the Opportunity

🟢 Low Risk — Stop vs. Stop

If both processes only stop the Lead cadence, the behavior is redundant but generally harmless.

🟡 Review Carefully — Opportunity Handoff

A conversion flow that enrolls the new Opportunity may conflict with the Enroll New Opportunities automation.

🔵 Support Action

Review both the Lead conversion process and Opportunity creation process before enabling new-Opportunity enrollment.

4. Stop Cadences When Lead Status Is Unqualified

What It Does

When a Lead’s Status changes to Unqualified, active cadences are stopped.

Trigger: Lead is updated and Status equals Unqualified.

Look for These Flows

Review active Lead flows that:

  • Run when Status changes to Unqualified

  • Stop active cadences

  • Change Status back to another value

  • Enroll another cadence after the stop action

🟢 Low Risk — Stop vs. Stop

Duplicate stop actions are usually harmless.

🟡 Review Carefully

Risk increases if the flow reverses the Status change or re-enrolls the Lead.

🔵 Support Action

If the flow only stops the cadence, recommend removing the redundancy when practical. If it performs additional work, review those actions before deactivation.

5. Stop Cadences for Selected Lead Statuses

What It Does

When a Lead’s Status changes to an administrator-selected value, active cadences are stopped.

Custom Lead Status values may be selected.

Trigger: Lead is updated and Status matches a configured value.

Look for These Flows

Review status-driven Lead Flows that:

  • Stop cadences

  • Reassign ownership

  • Send notifications

  • Enroll another cadence

  • Change Status again

  • Perform additional actions on the same Status values

🟢 Low Risk — Stop vs. Stop

Duplicate stop logic is generally harmless.

🟡 Review Carefully

A flow may perform business-critical actions in addition to stopping the cadence.

🔵 Support Action

Compare the exact Status values selected in Cadence Setup with each applicable flow branch. Do not deactivate a flow solely because it includes a stop action if it also performs unrelated work the customer needs.

6. After-Hours Override

What It Does

When the After-Hours Override is enabled and a template is selected, cadence steps scheduled to send immediately are replaced with one override SMS or email when a Cadence Library is applied to a Lead outside configured business hours.

This applies whether the cadence is enrolled:

  • Manually

  • Through a Flow

  • Through Cadence Automations

  • Through another supported process

For example, if three steps are scheduled to send immediately, the Lead receives one override message instead.

The replaced steps appear in the cadence timeline as:

Completed with override

Trigger: A Cadence Library is applied to a Lead outside configured business hours and one or more initial steps are scheduled immediately.

Timing Distinction

The business days and hours configured for the After-Hours Override apply only to this automation.

They do not change the Cadence batch job window. The batch job window continues to control non-immediate scheduled messages separately.

Look for These Flows

Review active flows that:

  • Send an after-hours acknowledgement

  • Send a “we’ll get back to you soon” SMS or email

  • Delay communication until business hours

  • Suppress messages based on time of day

  • Send direct SMS or email communication for new after-hours Leads

🟡 Review Carefully — Risk of Duplicate Communication

The Lead may receive both the After-Hours Override and the flow-generated message.

🔵 Support Action

The override is intended to be the single immediate after-hours response.

Recommend one of the following:

  • Deactivate the existing after-hours flow and use the override.

  • Keep the flow and leave the After-Hours Override disabled.

Opportunity Automations

7. Enroll New Opportunities

What It Does

When an Opportunity is created, the selected Cadence Library is enrolled.

Trigger: Opportunity is created.

Look for These Flows

Review active Opportunity Flows that:

  • Run when an Opportunity is created

  • Enroll a cadence

  • Create follow-up SMS, email, or tasks directly

Also review Lead conversion Flows that:

  • Create an Opportunity

  • Enroll the resulting Opportunity

  • Copy cadence behavior from the converted Lead

🔴 High Risk — Enroll vs. Enroll

The Opportunity may be enrolled in multiple Cadence Libraries.

🟡 Review Carefully — Converted Opportunities

Lead conversion logic may enroll the Opportunity before the new-record automation runs.

🔵 Support Action

Trace the complete Lead-to-Opportunity handoff and select one Opportunity enrollment process.

8. Appointment Set Trigger

What It Does

When the Appointment Date/Time field on an Opportunity is populated or changed:

  1. The active cadence is stopped.

  2. The selected appointment Cadence Library is enrolled.

The automation may run when the appointment is first scheduled and when it is rescheduled.

Trigger: Opportunity is updated and Appointment Date/Time changes.

Look for These Flows

Review active Opportunity flows that:

  • Use ISCHANGED() on Appointment Date/Time

  • Send reminder emails

  • Send reminder SMS messages

  • Create reminder tasks

  • Enroll an appointment reminder cadence

  • Replace or reschedule reminder activity

🔴 High Risk — Duplicate Reminders

The customer may receive both the flow-generated reminder and the cadence reminder.

🟡 Review Carefully

Some reminder flows perform additional work, such as creating internal tasks or updating fields.

🔵 Support Action

Identify the customer’s current reminder process and consolidate it into one method. Confirm that any additional Flow actions are preserved if the flow is deactivated.

9. Opportunity Follow-Up Status Trigger

What It Does

When an Opportunity’s Status changes to Follow Up:

  1. The active cadence is stopped.

  2. The selected follow-up Cadence Library is enrolled.

Trigger: Opportunity is updated and Status changes to Follow Up.

Look for These Flows

Review active Opportunity flows that:

  • Run when Status changes to Follow Up

  • Stop an active cadence

  • Enroll a follow-up cadence

  • Swap cadence libraries based on Status

🔴 High Risk — Enroll vs. Enroll

Both processes may enroll the follow-up Cadence Library.

🔴 High Risk — Fighting Automations

One process may re-add a cadence the other process stopped.

🔵 Support Action

Select one process to control the Follow Up transition and deactivate the overlapping process.

10. Stop Cadences for Selected Opportunity Stages

What It Does

When an Opportunity moves to an administrator-selected Stage, active cadences are stopped.

Trigger: Opportunity is updated and Stage matches a configured value.

Look for These Flows

Review Stage-driven Opportunity flows, especially those that run for:

  • Closed Won

  • Closed Lost

  • Contract Signed

  • Appointment Completed

  • Cancelled

  • Custom Stages

Determine whether the Flow:

  • Stops a cadence

  • Enrolls another cadence

  • Sends notifications

  • Updates ownership

  • Creates a Transaction

  • Performs other business-critical actions

🟢 Low Risk — Stop vs. Stop

Duplicate stop actions are usually harmless.

🟡 Review Carefully

Stage-driven flows often perform more than cadence management.

🔵 Support Action

Compare the selected Stage values with every applicable flow branch before recommending any change.

Library-Level Automations

16. Chain to Another Library on Completion

What It Does

When every step in the current Cadence Library is complete, the record is automatically enrolled in the selected next library.

Common uses include:

  • Initial outreach followed by long-term nurture

  • Appointment follow-up followed by ongoing communication

  • A short introductory cadence followed by a longer sequence

Trigger: The final step of the current Cadence Library completes.

Look for These Flows

Review active Flows that:

  • Monitor Cadences__c status

  • Watch a cadence-complete field

  • React to a cadence completion task

  • Enroll another Cadence Library

  • Re-enroll the original library

  • Create a loop between two libraries

Chaining Loop Example

A loop may occur when:

  • Library A chains to Library B using Cadence automations.

  • A flow enrolls Library A again when Library B completes.

🔴 High Risk — Double Chaining

A native chain and completion flow may both enroll the next library.

🔴 High Risk — Chaining Loop

A record may move repeatedly between Cadence Libraries.

🔵 Support Action

Use either native chaining or the completion Flow, but not both. Native chaining is generally simpler when the customer only needs a direct library-to-library handoff.

Known Limitation: Silent Chain Skip

If the destination Cadence Library is:

  • Archived

  • In Draft

  • Deleted

…the chain is skipped and no error is displayed.

🟣 Known Limitation

When a customer reports that the next cadence did not start, check the destination Cadence Library’s status first.

Support Review Checklist

Before advising a customer to enable an automation, confirm:

  • ☐ The relevant Readiness Check results were reviewed.

  • ☐ Only active flows were treated as immediate conflicts.

  • ☐ The flow and automation triggers were compared.

  • ☐ Entry conditions and ISCHANGED() logic were reviewed.

  • ☐ Flow actions were documented.

  • ☐ Related-object flows were considered where applicable.

  • ☐ The customer selected one method for each overlapping process.

  • ☐ Retired flows were deactivated rather than deleted.

  • ☐ The change was tested with a controlled record.

  • ☐ Enrollment, messaging, stop, and handoff behavior were verified.

Escalation Guidelines

Escalate for additional technical review when:

  • The Readiness Check does not identify a flow that clearly overlaps.

  • The automation and flow appear unrelated, but duplicate enrollment still occurs.

  • Order-of-execution behavior cannot be determined.

  • A cadence is repeatedly stopped and re-enrolled.

  • A chain fails while the destination Cadence Library is Active.

  • The customer’s routing requirements exceed supported automation options.

  • A complex Flow performs business-critical actions that cannot be separated safely from cadence management.

Include the following with the escalation:

  • Object

  • Cadence automation being enabled

  • Flow Label

  • Flow API Name

  • Trigger type

  • Entry conditions

  • Relevant Flow actions

  • Cadence Library names

  • Test record ID

  • Expected behavior

  • Actual behavior
